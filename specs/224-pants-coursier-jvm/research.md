## R1 — Coursier lockfile TOML schema (Pants 2.x)

<!-- verified: 2026-08-01 against
     https://raw.githubusercontent.com/pantsbuild/example-jvm/main/3rdparty/jvm/default.lock
     (Pants's canonical JVM example) -->

**Decision**: Parse the coursier lockfile as a TOML document with the
schema shape below. Only extract the fields waybill needs — the header
metadata comment block is parsed separately from the TOML body.

**Concrete shape** (verified empirically):

```text
# This lockfile was autogenerated by Pants. To regenerate, run:
#
#    pants generate-lockfiles
#
# --- BEGIN PANTS LOCKFILE METADATA: DO NOT EDIT OR REMOVE ---
# {
#   "version": 1,
#   "generated_with_requirements": [
#     "com.google.guava:guava:31.0.1-jre,url=not_provided,jar=not_provided",
#     "org.scala-lang:scala-library:2.13.8,url=not_provided,jar=not_provided"
#   ]
# }
# --- END PANTS LOCKFILE METADATA ---

[[entries]]
directDependencies = []
dependencies = []
file_name = "com.google.code.findbugs_jsr305_3.0.2.jar"

[entries.coord]
group = "com.google.code.findbugs"
artifact = "jsr305"
version = "3.0.2"
packaging = "jar"

[entries.file_digest]
fingerprint = "766ad2a0783f2687962c8ad74ceecc38a28b9f72a2d085ee438b7813e928d0c7"
serialized_bytes_length = 19936

[[entries]]
...
```

**Extraction rules**:

1. **Pants-header discrimination (FR-011)**: before TOML parsing, scan
   the raw file bytes for the substring
   `# --- BEGIN PANTS LOCKFILE METADATA`. If absent, log INFO ("not a
   Pants-generated coursier lockfile; skipping") and return without
   further parsing. This prevents false-positive discovery of
   standalone coursier lockfiles that operators may have in the same
   `3rdparty/jvm/` directory for non-Pants purposes.
2. **Metadata version guard**: after the Pants-header substring
   matches, extract the JSON block between `BEGIN` / `END` markers by
   line-scan (strip leading `# ` from each line, concat, parse as
   JSON). Verify `metadata.version == 1`. Any other value → WARN
   ("unsupported Pants coursier metadata version <N>; skipping") +
   skip the file. This is separate from any hypothetical future TOML
   schema changes; the metadata version tracks the semantic content
   of the entire lockfile.
3. **TOML body parse**: strip the header comment block, parse the
   remainder with `toml::from_str::<CoursierLockfile>()`. On parse
   error → WARN + skip.
4. **Component identity**: `[entries.coord].group` + `.artifact` +
   `.version` → `pkg:maven/<group>/<artifact>@<version>`. Group is
   used verbatim (already dot-separated per Maven convention). All
   three segments are `encode_purl_segment`-encoded via the shared
   helper (R3).
5. **Classifier / packaging PURL qualifiers** (FR-002): if
   `[entries.coord].classifier` is present AND non-empty, append
   `?classifier=<value>` to the PURL. If `[entries.coord].packaging`
   is present AND != `"jar"` (Maven default), append `&type=<value>`
   (or `?type=<value>` if no classifier came before). Both are
   `encode_purl_segment`-encoded.
6. **Hashes** (FR-002): `[entries.file_digest].fingerprint` becomes
   one `ContentHash` with `HashAlgorithm::Sha256`. Absent
   `file_digest` block → empty `hashes[]` vector + INFO log for
   diagnostics.
7. **Dependency edges** (FR-003): `[[entries]].dependencies[]` is an
   array of coordinate strings — see R2 for parse rules. Extracted
   coord triples are converted to normalized `group:artifact:version`
   for the `depends` field on `PackageDbEntry`. Downstream graph
   resolution matches on these strings.
8. **License**: NOT present in coursier lockfile format (empirically
   confirmed — no `[entries.license]` block or license field in the
   Pants example-jvm lockfile). FR-002's license clause is a null
   contract (matches m223's pex-lockfile posture verbatim). Licenses
   come from downstream enrichment (deps.dev / ClearlyDefined).

**Alternatives considered**:

- **Skip the Pants-header discrimination (FR-011), parse every
  `3rdparty/jvm/*.lock` file as if Pants-generated** — rejected:
  false-positive risk on standalone coursier lockfiles that some
  operators may keep in the same directory for non-Pants build
  tooling. INFO log lets operators see what waybill skipped and why.
- **Parse the metadata JSON via a full JSON parser inside the
  TOML-comment scan** — accepted (done). The metadata block is bounded
  by literal `BEGIN` / `END` markers and each line starts with `# `;
  strip-and-concat then `serde_json::from_str` is straightforward.
- **Ignore `packaging` when it equals `"jar"`** — accepted for PURL
  qualifier omission (Maven default is `jar`, so `?type=jar` is
  redundant). Matches purl-spec's maven-type canonical shape.
- **Use `toml::Value` bag types and dig via `.get()` chains** —
  rejected per Principle IV. Explicit `#[derive(Deserialize)]` types
  are the standard.

## R2 — Coordinate-string parse format (dependency edges)

<!-- verified: 2026-08-01 against Pants example-jvm generated_with_requirements block -->

**Decision**: Parse `"group:artifact:version[,url=X,jar=Y,...]"`
coordinate strings by splitting on the FIRST comma to separate the
coord triple from the trailing metadata, then splitting the coord
triple on colons (exactly 2 colons expected). Trailing metadata
(`url=`, `jar=`, and any future additions) is discarded — waybill
records only the coord triple.

**Grammar** (informal EBNF):

```text
coord_string  = coord_triple ("," metadata_kv ("," metadata_kv)*)?
coord_triple  = group ":" artifact ":" version
group         = [any char except ':' and ',']+
artifact      = [any char except ':' and ',']+
version       = [any char except ',']+   ; version can contain ':' (rare)
metadata_kv   = key "=" value
key           = [a-zA-Z_]+
value         = [any char except ',']+
```

**Concrete examples** (from Pants example-jvm):
- `"com.google.guava:guava:31.0.1-jre,url=not_provided,jar=not_provided"`
  → group=`com.google.guava`, artifact=`guava`, version=`31.0.1-jre`
- `"com.lihaoyi:acyclic_2.13:0.2.1,url=not_provided,jar=not_provided"`
  → group=`com.lihaoyi`, artifact=`acyclic_2.13`, version=`0.2.1`
- `"org.scala-lang:scala-library:2.13.8"` (metadata may be absent)
  → group=`org.scala-lang`, artifact=`scala-library`, version=`2.13.8`

**Rust implementation** (in `pants_jvm/coordinate.rs`):

```rust
pub(crate) struct Coordinate {
    pub group: String,
    pub artifact: String,
    pub version: String,
}

pub(crate) fn parse_coord_string(s: &str) -> Option<Coordinate> {
    let coord_part = s.split_once(',').map(|(c, _)| c).unwrap_or(s);
    let mut parts = coord_part.splitn(3, ':');
    let group = parts.next()?.trim().to_string();
    let artifact = parts.next()?.trim().to_string();
    let version = parts.next()?.trim().to_string();
    if group.is_empty() || artifact.is_empty() || version.is_empty() {
        return None;
    }
    Some(Coordinate { group, artifact, version })
}
```

**Rationale**:
- `split_once(',')` gets the coord triple even if trailing metadata
  is absent or contains commas after the first (safer than `split(',')` +
  positional access).
- `splitn(3, ':')` ensures the third segment (version) captures any
  colons within (rare but possible — e.g., some legacy Maven versions
  with `:` in them).
- Empty-segment guard filters out malformed entries; caller logs a WARN.

**Alternatives considered**:

- **Use a `nom` or `winnow` parser** — rejected: adds a new dependency
  for a shape that fits in 10 lines of `str::split_once` calls.
  Principle I-friendly minimalism.
- **Regex** — rejected: `regex` is already a workspace dep so this is
  technically free, but a regex compilation per call (or a `OnceLock`
  static) is heavier than the split-once approach for a shape this
  simple.

## R3 — Maven PURL construction (reuse existing helper, promote visibility)

**Decision**: Reuse `maven::build_maven_purl` at
`waybill-cli/src/scan_fs/package_db/maven.rs:2365`. Currently
module-private (`fn`); promote to `pub(crate)` in T003 so
`pants_jvm/lockfile.rs` can import it via
`crate::scan_fs::package_db::maven::build_maven_purl`.

This mirrors m223's T003 pattern where `pip::normalize_pypi_name_for_purl`
was already `pub(crate)` for exactly this cross-reader reuse.

**Classifier + packaging handling**: `build_maven_purl` at line 2365
does NOT currently accept classifier/packaging arguments (it takes
only group/artifact/version). Two options:

- **Option A (recommended)**: extend `build_maven_purl` to accept
  optional classifier + packaging, returning `Option<Purl>`. Existing
  callsites pass `None` explicitly. Small refactor at maven.rs; adds
  robustness for future callers (Gradle reader could use it too).
- **Option B**: pants_jvm builds the PURL string inline, matching the
  inline pattern at maven.rs:1787-1796 (which is what the existing
  Maven-ancestor path does). Copy-paste, but scoped and low-risk.

**Chosen**: Option B for the v1 ship. Rationale: modifying `build_maven_purl`
signature ripples to every callsite in maven.rs (several) and would
warrant its own separate refactor spec. Option B keeps m224 additive-only
in maven.rs (just the visibility promotion in T003). Option A is filed
as a follow-up refactor.

**PURL construction pattern (Option B, inline in pants_jvm)**:

```rust
let mut purl_str = format!(
    "pkg:maven/{}/{}@{}",
    encode_purl_segment(&coord.group),
    encode_purl_segment(&coord.artifact),
    encode_purl_segment(&coord.version),
);
let has_classifier = coord.classifier.as_deref().is_some_and(|c| !c.is_empty());
let has_packaging = coord.packaging.as_deref().is_some_and(|p| !p.is_empty() && p != "jar");
if has_classifier || has_packaging {
    purl_str.push('?');
    let mut sep = "";
    if let Some(c) = coord.classifier.as_deref().filter(|c| !c.is_empty()) {
        purl_str.push_str("classifier=");
        purl_str.push_str(&encode_purl_segment(c));
        sep = "&";
    }
    if let Some(p) = coord.packaging.as_deref().filter(|p| !p.is_empty() && *p != "jar") {
        purl_str.push_str(sep);
        purl_str.push_str("type=");
        purl_str.push_str(&encode_purl_segment(p));
    }
}
```

**Rationale**:
- Matches purl-spec's `maven` type qualifier rules exactly.
- Skipping `type=jar` (the Maven default) preserves the canonical
  PURL shape and matches the existing Maven reader's ancestor emission.
- Matching existing pattern minimizes cross-reader drift.

## R4 — `pants.toml` `[jvm]` config schema (minimal, decoupled)

**Decision**: Parse `pants.toml` with `toml = "0.8"` (already a
workspace dep). Extract only two fields: `[jvm].default_resolve`
(default resolve name, defaults to `"default"` when absent) and
`[jvm.resolves]` (map of resolve name → lockfile path, relative to
scan root). Everything else ignored. Missing / unparseable → falls
back to FR-001 default glob per FR-004.

**Concrete `pants.toml` shape**:

```toml
[jvm]
default_resolve = "prod"

[jvm.resolves]
prod = "build-support/jvm/prod.lock"
junit = "3rdparty/jvm/junit.lock"
scalatest = "3rdparty/jvm/scalatest.lock"
```

**Rust type**:

```rust
#[derive(Debug, Default, Deserialize)]
struct PantsConfig {
    #[serde(default)]
    jvm: JvmSection,
}

#[derive(Debug, Default, Deserialize)]
struct JvmSection {
    #[serde(default)]
    default_resolve: Option<String>,
    #[serde(default)]
    resolves: std::collections::HashMap<String, String>,
}
```

**Rationale**:
- Mirrors m223's Python-side `PantsConfig` shape. Same fail-open
  contract (missing config keys → `None` / empty map → default glob
  fallback).
- `resolves` map is a first-class TOML table — no ambiguity about
  key names or value shapes.
- `default_resolve` is optional; when absent, waybill uses the
  filename stem of each discovered lockfile as the resolve name
  (matches m223 posture).

**Discovery merge**:
1. Default glob `3rdparty/jvm/*.lock` → for each match, resolve
   name = filename stem.
2. `[jvm.resolves]` entries → for each `(name, path)`, if `path`
   exists on disk and is not already discovered via glob, add with
   `resolve_name = name` (config-declared name wins for the
   `waybill:pants-resolve` annotation).
3. If both sources discover the same path, glob-side is kept +
   config-declared name is preferred (INFO log noting the
   name-override).

**Note on m223 sharing**: m223's `pants/config.rs` parses `[python]`.
m224's `pants_jvm/config.rs` parses `[jvm]`. Two separate files
because the sections are semantically distinct. A shared TOP-level
`PantsRootConfig` that unions `[python]` + `[jvm]` was considered but
rejected — the two backends are independently addable / removable and
sharing coupling would create maintenance friction. Small drift-risk
acceptable.

## R5 — Fixture strategy + coordinate-string edge cases

**Decision**: Ship 7 synthetic fixtures under
`waybill-cli/tests/fixtures/pants_coursier_jvm/`:

1. `minimal_jvm/` — US1 baseline: 3 synthetic entries
   (`dev.waybill.fixture:core:1.0.0`, `dev.waybill.fixture:util:1.0.0`,
   `dev.waybill.fixture:api:1.0.0`), each with 1 sha256 fingerprint.
   Include one `dependencies[]` edge (`api` depends on `core`) for
   FR-003 coverage.
2. `multi_resolve/` — US1 scenario 4: `default.lock` + `junit.lock` +
   `scalatest.lock`, 2 entries each. Different fixture names per
   resolve.
3. `pants_toml_custom_path/` — US3: `pants.toml` declaring
   `[jvm.resolves] prod = "build-support/jvm/prod.lock"` + lockfile
   at that path; no file at `3rdparty/jvm/`.
4. `with_pom_xml/` — US2 dedup: `default.lock` +
   `pom.xml`, both declaring `dev.waybill.fixture:shared:1.0.0`.
5. `with_classifier/` — FR-002 PURL qualifier coverage: one entry with
   `packaging = "war"` (non-default), one entry with a `classifier`
   field. Exercises the classifier + type PURL emission.
6. `non_pants_coursier/` — FR-011: valid TOML matching the coursier
   shape but WITHOUT the `# --- BEGIN PANTS LOCKFILE METADATA`
   header. Waybill must skip with INFO log.
7. `corrupt_lockfile/` — SC-005: intentionally truncated / malformed
   TOML after the Pants header (so the header-discriminator passes
   but body-parse fails). Verifies fail-open WARN behavior.

Every fixture uses synthetic Maven coordinates (`dev.waybill.fixture:*`)
per `feedback_fixture_synthetic_package_names`. Fixture directory
lives in-repo (small — total < 25 KB) rather than the m090 sibling-repo
fixture cache; matches m223's fixture placement.

**Coordinate-string edge cases to cover in R2 unit tests**:

| Input | Expected result |
|-------|-----------------|
| `"g:a:v"` | `Some(Coordinate { g, a, v })` |
| `"g:a:v,url=X"` | `Some(Coordinate { g, a, v })` — metadata stripped |
| `"g:a:v,url=X,jar=Y"` | `Some(Coordinate { g, a, v })` |
| `"g:a"` | `None` — missing version |
| `"g:a:v:extra"` | `Some(Coordinate { g, a, v: "v:extra" })` — `splitn(3, ':')` captures the rest |
| `""` | `None` |
| `":a:v"` | `None` — empty group |
| `"g::v"` | `None` — empty artifact |
| `"g:a:"` | `None` — empty version |
| `"g:a:v,"` | `Some(Coordinate { g, a, v })` — trailing comma acceptable |
