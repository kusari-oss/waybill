# Implementation Plan: Accept coord-table `directDependencies` in Pants coursier-JVM lockfiles

**Branch**: `676-fix-jvm-coord-table` | **Date**: 2026-09-03 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/676-fix-jvm-coord-table/spec.md`

## Summary

Fix issue #756: the m224 Pants coursier-JVM reader silently drops the entire JVM resolve when its lockfile uses the coord-table form of `directDependencies`. Phase-0 research at `waybill-cli/src/scan_fs/package_db/pants_jvm/lockfile.rs:358` proved `direct_dependencies` is explicitly dead-code (`let _ = &entry.direct_dependencies;`) — the field is parsed but never consumed. Chosen fix: **drop the `direct_dependencies` field entirely** (spec Assumptions Option B), since preserving it via untagged enum only to discard the value is code-smell. This is the smallest possible diff that closes the bug + gains the maximum robustness (the parser now ignores the field at whatever shape upstream chooses). Re-enable the `pants-example-jvm` corpus target from PR #757 as the regression gate.
