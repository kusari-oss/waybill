## Phase 3 pre-implementation findings (2026-08-21)

Before landing any reader migration, sizing up the US1 pilot surfaced two structural findings the plan/research phase missed:

**Finding 1 — Per-scan config isn't carried by the current callback API.** Two of the 7 pilot readers (`ipk_file`, `rpm_file`) take `read()` parameters beyond `(rootfs, exclude_set)` (a `Reader...Config` struct plus derived per-scan state like `distro_tag`). Our `fn(&Path, &SharedWalkerContext<'_>)` callback signature is a plain function pointer and can't capture per-scan state.

**Resolution**: extended the registry API. `ReaderRegistration` gains `state: Option<Arc<dyn Any + Send + Sync>>`. `SharedWalkerContext::state::<T>(reader_id)` accessor lets a callback downcast to its concrete config type. Callback signatures unchanged. All 24 Phase 2 tests re-verified (each got a mechanical `state: None,` added). Applied at implementation time — no separate spec revision.

**Finding 2 — US1 pilot readers have hidden structural dependencies.**

- `pants_common` (T028) is NOT a top-level reader called from `read_all` — it's a helper (`discover_build_files`) shared by `pants_go` and `pants_shell` (both US2, T045-T047). Migrating pants_common alone doesn't remove any actual walker cost until pants_go + pants_shell migrate too.
- `yocto/recipe` (T029) looks like one walker site, but its `read()` also invokes `layer_conf::build_index()` and `bbappend::build_from_walk()` — each a separate walker in a sibling module (bundled as T059 in US2). And post-walker aggregation (`resolve_recipe_depends`, bbappend match-and-annotate) makes the single-file migration non-trivial.
- Likely more readers have similar hidden coupling — not audited beyond these two.

**Options considered**:
- **A. Reshape US1 pilot to pure "top-level, no hidden deps" readers only.** Keeping haskell + scala + erlang (all rootfs+exclude_set-only signatures). Drop or defer ipk_file, rpm_file, pants_common, yocto/recipe. New pilot saves ~641 ms → after 120 ms tax → 4.10s − 521 ms = 3.58s. Misses ≤ 3.0s target; approximately meets the ≤ 3.5s target if I1 patch is applied.
- **B. Do a proper per-reader audit before proceeding.** Read each of the 7 pilot readers end-to-end; identify shared helpers + post-walker steps; decide per-reader whether to migrate now, defer, or reshape US1.
- **C. Migrate the reader-group instead of the individual reader.** For pants: migrate `pants_common + pants_go + pants_shell` as one bundle. For yocto: `yocto/recipe + layer_conf + bbappend` as one bundle. Bigger PRs but fewer half-migrations.

**Current implementation state**: API extension landed (dispatch.rs, walker.rs, walk_context.rs, mod.rs, registry.rs). All 24 walk_registry tests + 5015 workspace tests pass. Zero readers migrated. Recommend pausing here to get user direction on options A/B/C before landing T026-T035.
