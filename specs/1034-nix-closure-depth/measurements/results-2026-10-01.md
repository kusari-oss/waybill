## What it settles

Almost every concern the issue raises is a property of the **build** closure,
not the runtime one:

- **Tension 1, bootstrap is noise for vulnerability matching.** The runtime
  closure contains zero bootstrap derivations. The noise is not present to be
  filtered.
- **Tension 2 / #744, a flood of no-PURL components.** The issue estimates
  "~1,300 components largely without PURLs". Build closure: 49.3% carry
  `pname` + `version`. Runtime closure: **99.7%**. The no-PURL problem is a
  build-closure problem.
- **Tension 3, which graph.** This is the question. 1,796 vs 726, and they
  differ in character as much as size.
- **Tension 5, cost.** Not a factor, more strongly than the issue assumed:
  the build closure enumerates in ~1 s, and the runtime closure needs **no
  realisation** — `nix path-info -r --store https://cache.nixos.org` reads it
  from narinfo metadata. The issue recorded the runtime closure as needing a
  build; it does not, for any substitutable path.

Shape of the answer the numbers support: **default to the runtime closure.**
498 → 726 is a 46% increase over what waybill emits today, almost all of it
software with real identity. Tiering (tension 4, reusing `--sbom-tier`) is
where the build closure belongs, and that is a separable later decision.

## Cross-system check (added 2026-10-01, same revision and attribute)

`x86_64-linux`, cross-evaluated from the `aarch64-darwin` host — no Linux
machine and no builder required, since evaluation is platform-independent and
`nix path-info --store https://cache.nixos.org` is metadata over HTTP:

| | aarch64-darwin | x86_64-linux |
|---|---:|---:|
| build closure | 1,796 derivations | **2,259 derivations** |
| build, name + version | 49.3% | **36.9%** |
| build, `bootstrap-*` | **40** | **40** |
| runtime closure | 726 store paths | **561 store paths** |
| runtime, name + version | **99.7%** | **99.3%** |
| runtime, `bootstrap-*` | **0** | **0** |
| build ÷ runtime | 2.47x | **4.03x** |

The pattern holds on both platforms and is *more* pronounced on Linux: a
larger build closure, worse build-side identity, a smaller and still ~99%
identifiable runtime closure. Both build closures carry exactly 40 bootstrap
derivations; neither runtime closure carries any.

The platform-specific machinery appears where the issue predicted — Linux
shows the gcc/glibc chain (`crt`, `libc.a`, `libgetopt.a`, `libtcc1.a`,
8 derivations each) in place of Darwin's clang/cctools/Apple-SDK. Darwin's
runtime closure retains a little of its toolchain (4 cctools, 2 apple-sdk,
1 clang-wrapper); Linux's retains essentially none.

So the recommendation does not depend on the platform.

## Not measured — do not generalise past this

- One package, one revision. Two systems now, but still HLS only: the
  build-vs-runtime **ratio** is the finding, and the absolute counts are not
  general across packages.
- `nixpkgs`' HLS is 2.13.0.0; the corpus source tree is 2.15.0.0.
- Whether any advisory source keys on anything in the build-only layer —
  still open, and still the strongest argument either way for tension 1.
- What a consumer does with a bootstrap-tier component. Still unmeasured, and
  the issue is right that if the answer is "filters it out", that argues for
  tiering over depth.

## Schema traps that produced wrong numbers first

Both are documented in `classify-closure.py`, and both yielded a confident
wrong figure before being caught:

1. `nix derivation show` schema v4 keeps `name` at the top level of each
   derivation, and for `structuredAttrs` derivations `pname`/`version` live in
   `structuredAttrs`, not `env`. Reading `env` alone scored 889 of 1,796
   derivations as nameless. Caught only by cross-checking the issue's
   distinct-name count.
2. Nix multi-output store paths end in the output name, not the version —
   `ncurses-6.6-dev`, `shake-0.19.9-data`. A version regex anchored at
   end-of-string understated runtime identity as 50.7% against the true 99.7%.

Residual discrepancy: distinct build-closure names come out 1,326 here against
the issue's 1,319. 0.5%, unexplained, probably a difference in how names were
counted. Flagged rather than reconciled.
