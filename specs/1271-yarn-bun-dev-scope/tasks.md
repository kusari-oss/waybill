# Tasks: yarn and bun development scope

**Input**: Design documents from `/specs/1271-yarn-bun-dev-scope/`
**Prerequisites**: plan.md, spec.md, research.md, data-model.md, contracts/

**Tests**: Included. The spec requires them — SC-005 demands an explicit
regression control per edge case, and SC-006 through SC-008 require tests
that fail if a diagnostic or a limitation changes.

**Organization**: By user story, so each ships independently. US1 (bun) is
the MVP: the axis is in the lockfile, so it needs no manifest path and no
traversal.

- **[P]**: parallelizable — different file, no dependency on incomplete work

## Fixture authoring rule, applies to every fixture task

Fixtures are **hand-written**, not generated by the package managers, because
synthetic `waybill-fixture-*` coordinates cannot be resolved from a registry
and real coordinates are forbidden in committed fixtures. The probe output in
`measurements/` is the shape authority: copy the structure, substitute
synthetic names and placeholder `sha512-` digests, exactly as the existing
`waybill-cli/tests/fixtures/bun_lock/minimal_repro/bun.lock` does.

## Dependencies

```text
Phase 1 (T001-T009, all parallel)
  └─> Phase 2 (T010-T012)          baselines; blocking, see research R5
        ├─> Phase 3 US1 (T013-T019)   bun; independent
        └─> Phase 4 US2 (T020-T029)   yarn; independent of US1
              └─> Phase 5 US3 (T030-T035)  diagnostics; needs US2's evidence path
                    └─> Phase 6 (T036-T042)
```

US1 and US2 touch different files and can run concurrently once Phase 2 is
done. US3 depends on US2 only — bun emits none of these diagnostics by
design (T018).

Within a story, the test tasks precede their implementation: T013-T014 before
T015-T017, T020-T021 before T022-T027, T034-T035 after T032-T033 because
they assert diagnostics that must exist to be asserted.

## Parallel execution

- **Phase 1**: all nine fixture tasks at once — nine directories, no shared file.
- **Phase 3 vs Phase 4**: `bun_lock.rs` and `yarn_lock.rs` are different files; only T022 touches `mod.rs`.
- **Phase 5**: T030 and T031 are independent fixtures.
- **Phase 6**: T038, T039 and T040 are independent; T036, T037, T041 and T042 are verification and run last.

## Implementation strategy

**MVP is US1 alone.** bun's evidence is self-contained, so it needs no
manifest reading, no member discovery and no traversal — three of the four
things that can go wrong here. Landing it first also proves the
classification contract against a real fixture before the harder evidence
path depends on it.

Then US2, which is where the risk is: two dialects, two `workspaces`
spellings, member discovery and the exclusion interaction. Then US3, which is
small once US2's outcome enumeration exists.

Phase 2 is not optional and not reorderable. Once a reader changes, there is
no way to tell an introduced disagreement from a pre-existing one, and FR-007
turns on exactly that distinction.
