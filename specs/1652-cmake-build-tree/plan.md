# Implementation Plan: Read a CMake build tree to settle what a build actually used (#1535)

**Branch**: `1652-cmake-build-tree` | **Date**: 2026-11-24 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `specs/1652-cmake-build-tree/spec.md`

## Summary

An operator names one or more CMake build trees with a new repeatable
`--cmake-build-tree <PATH>` flag on `waybill sbom scan`. waybill finds every
CMake build directory (one with a `CMakeCache.txt`) beneath each path and
reads four kinds of file:
- the cache;
- FetchContent's `_deps/` population directories;
- ExternalProject download stamps;
- `compile_commands.json`, plus a CMake file-API reply when one is present.

From these it does four things:
1. **Settles each fetch declaration** the source scan already emits: *taken*,
   *not taken*, *incomplete* or *no evidence*. A *taken* declaration is in
   scope, whatever spec 1538 or 1641 said.
2. **Feeds the configured cache values** into spec 1641's condition evaluator,
   including string comparisons (#1656).
3. **Emits build-only components**, for populations no source declaration
   accounts for.
4. **Adds compile-time edges** from `compile_commands.json` include
   directories.

Without the flag, nothing changes.

The SC-001(a) probe (24 real build trees: CMake 3.25, 3.31, 4.0 × Ninja,
Make) fixed the signals (research R1–R3). FetchContent is settled from the
cache, at configure time. ExternalProject is settled from the
`<name>-download` stamp, located by file name because `PREFIX` and
`STAMP_DIR` can move it. Info files are not read. SC-001(b), a partial
TheRock build in CI, is still open and is task 1.

## Technical Context

**Language/Version**: Rust stable, pinned by `rust-toolchain.toml` (1.98.1). No nightly; `waybill-ebpf` untouched. No `+toolchain` on the gate (#1189).
**Primary Dependencies**: Existing only.
- `regex`: CMake `MATCHES` in the evaluator.
- `serde_json`: `compile_commands.json`, file-API replies, annotation values.
- `tracing`: the census and the INFO summary.
- `clap`: the new flag.
- `anyhow`/`thiserror`.

**Zero new Cargo dependencies** (FR-015).
**Storage**: N/A. Everything is in process for one scan.
**Testing**: `cargo test --workspace`. New integration suite `waybill-cli/tests/cmake_build_tree.rs`, built on `tests/common/cmake_fetch.rs::scan(fx, path, extra)`. Its fixture build trees are committed: they are generated by the probe and then reduced to the files read (research R9), with paths rewritten.
**Target Platform**: Linux, macOS, Windows, the same as the scan path. Build trees are read as files, so no CMake is needed at scan time.
**Project Type**: CLI (single crate `waybill-cli`).
**Performance Goals**: SC-008: source+build at most 1.10× source-only on the fixtures, median of 3. Re-checked on TheRock after SC-001(b).
**Constraints**:
- Read-only.
- No absolute host path in any output (FR-006).
- Byte-identical output without the flag (SC-004).
- Stamp files are tested for existence only (R9).

**Scale/Scope**: The probe has 198–481 entries per build tree. TheRock is unknown until SC-001(b); expect hundreds of build directories, one per subproject plus nested `_deps`.

CycloneDX 1.6, SPDX 2.3 and SPDX 3 have no field for "this fetch's outcome in a build, and its basis". | IX. Accuracy | Improved. Fallbacks that did not fire stay optional with evidence. Absence alone never narrows scope (research R2). |

**Structure Decision**: The new code lives under `package_db/cmake/` because
its two consumers are the fetch reader and the condition evaluator there.
Building on the milestone-109 observer in `scan_fs/binary/source_binding/`
was rejected:
- it runs only with `--fingerprints-corpus`;
- it never reads the cache;
- it joins FetchContent only;
- it serves fingerprint attribution, not scope.

It is left unchanged. Moving it onto `BuildEvidence` is a possible follow-up,
outside this spec.

## Complexity Tracking

| Deviation | Why needed | Simpler alternative rejected because |
|---|---|---|
| A new environment-variable side channel (`WAYBILL_CMAKE_BUILD_TREES`) | `read_all` takes positional arguments and has no context struct (#1483). Each neighbouring CMake flag already uses this pattern. | Adding a tenth positional argument through `scan_path` → `read_all` → `run_shared_walker_pilot` touches 75 call sites, for something #1483's `ScanContext` will replace. |
| Extending the evaluator to string values | FR-005 and #1656. Configured `STRING` values are the main thing a build tree adds. | Booleans only would leave the probe's `BACKEND STREQUAL "B"` unknown, which is the case R5 measured. |
